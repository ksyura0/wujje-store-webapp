# CLAUDE.md — Обязательные правила разработки Wujje Store

**Этот файл содержит строгие правила, которые CLAUDE обязан проверять и соблюдать перед любыми изменениями в коде.**

## 1. Правило бэкапов (СТРОГОЕ)

Перед внесением **крупных правок** в `index.html`, стили или логику Web3/оплаты:

- ✅ Создавай резервную копию текущей рабочей версии в папку `backups/`
- ✅ Используй формат имени: `index_YYYY-MM-DD_HH-MM.html` (пример: `backups/index_2026-11-24_15-00.html`)
- ✅ Когда пользователь пишет **«проверил, всё нравится»** или **подтверждает, что текущая версия работает отлично** → сразу сохраняй свежий эталонный бэкап с пометкой `_verified` (пример: `backups/index_VERIFIED_2026-11-24_15-30.html`)

**Когда это обязательно:**
- Изменения в структуре HTML (добавление/удаление экранов, модалей)
- Правки в CSS (новые анимации, переход между темами, изменение макета)
- Изменения в логике оплаты, Web3-кошельков, балансов
- Крупные функциональные добавления

**Когда можно пропустить:**
- Правки в текстовом контенте или конфигах
- Простые bug-fixes
- Удаление debug console.log

## 2. Защита кликабельности и видимости

**НИКОГДА** не оставляй скрытые элементы активными. Это блокирует интерфейс.

✅ **Все скрытые/невидимые элементы ОБЯЗАНЫ иметь:**
```css
.hidden-element {
  display: none;        /* или visibility: hidden */
  pointer-events: none; /* КРИТИЧНО! Запретить клики */
}
```

✅ **Правила для модальных окон и оверлеев:**
- Когда модаль/оверлей закрыта → `display: none` + `pointer-events: none`
- Когда открыта → `display: block` + `pointer-events: auto`
- Нельзя оставлять `pointer-events: auto` на скрытых элементах

✅ **Базовый контент (шапка, карточки, нижнее меню) ВСЕГДА должен быть виден** даже если:
- JS не загрузился
- Анимации не сработали
- Нет CSS-переходов

## 3. Сохранность Web3 и оплаты

**При изменении дизайна, тем или анимаций ЗАПРЕЩЕНО менять:**
- Логику подключения кошельков (`tonConnectUI`)
- Проверку статуса транзакций
- Обработчики кликов на кнопки оплаты
- API-вызовы и валидацию данных

❌ **Это запрещено без явного запроса пользователя:**
- Менять `CONFIG.RECEIVER_WALLET`
- Удалять или переименовывать элементы с ID, связанные с оплатой (`#payBtn`, `#tonConnect`, и т.д.)
- Менять структуру данных заказов (`order.rubAmount`, `order.target`, и т.д.)

✅ **Это можно делать свободно:**
- Добавлять CSS-анимации к кнопкам оплаты
- Менять цвета в темах
- Улучшать UX экрана оплаты

## 4. Чистота и проверка

**После ЛЮБЫХ правок в `index.html` ОБЯЗАТЕЛЬНО:**

1. ✅ Проверить **закрытие всех HTML-тегов** (не должно быть некрытых `<div>`, `<button>`, и т.д.)
2. ✅ Проверить **синтаксис внутри `<script>` блоков** (правильные скобки, кавычки, точки с запятой)
3. ✅ Проверить **синтаксис CSS** в `<style>` (правильные селекторы, закрытые фигурные скобки)
4. ✅ Убедиться, что **нет console.log() и console.error()** в production-коде
5. ✅ Запустить быструю визуальную проверку: видны ли шапка, карточки, нижнее меню, кнопки?

## 5. Предварительная проверка перед GitHub (Pre-Push Audit)

**ОБЯЗАТЕЛЬНЫЙ АУДИТ перед каждым `git commit` и `git push`:**

Прежде чем отправить код на GitHub, ты обязан провести полный аудит своего же кода.

### 5.1 Синтаксис и HTML-структура

✅ **Проверить:**
- Все теги `<div>`, `<button>`, `<form>`, `<svg>`, `<script>`, `<style>` **закрыты**
- Нет дублирующихся `id=""` атрибутов (каждый ID должен быть уникален)
- Все атрибуты имеют правильный синтаксис (кавычки, знаки равенства)
- Нет нарушенных вложений (например, `<button><div></button></div>`)

```bash
# Команда для проверки (в корне проекта):
grep -n 'id="' index.html | sort | uniq -d  # показывает дублирующиеся ID
```

### 5.2 Проверка JavaScript синтаксиса

✅ **КРИТИЧНО перед push:**
1. Извлечь весь код из `<script>` блоков
2. Проверить через `node --check script.js` (если Node доступен)
3. Вручную проверить:
   - Все `{` закрыты с `}`
   - Все `(` закрыты с `)`
   - Все строки в кавычках закрыты
   - Нет `console.log()`, `console.error()` в production коде

✅ **ОСОБЕННО ВАЖНО — Безопасные обращения к DOM:**
- Любое `document.getElementById(...)` или `document.querySelector(...)` ДОЛЖНО либо:
  - Иметь проверку: `if (el) { ... }`
  - Или использовать optional chaining: `?.` (например, `el?.classList`)
- **НИКОГДА** не делай так:
  ```js
  // ❌ КРИВО — упадёт если элемента нет
  document.getElementById("someId").innerHTML = "text";
  
  // ✅ ПРАВИЛЬНО:
  const el = document.getElementById("someId");
  if (el) el.innerHTML = "text";
  
  // ✅ ТАКЖЕ ПРАВИЛЬНО:
  document.getElementById("someId")?.innerHTML = "text";
  ```

### 5.3 Проверка рендера и кликов

✅ **Убедиться, что:**
- Нет скрытых элементов с `pointer-events: auto` (они блокируют интерфейс)
- Все скрытые элементы имеют `display: none` + `pointer-events: none`
- Базовый контент видим (шапка, карточки, нижнее меню)
- Все кнопки кликабельны
- Нет зависших модальных окон или оверлеев

```css
/* ❌ КРИВО */
.hidden-modal {
  display: none;
  pointer-events: auto;  /* ← это блокирует клики под модалью! */
}

/* ✅ ПРАВИЛЬНО */
.hidden-modal {
  display: none;
  pointer-events: none;
}
```

### 5.4 Порядок действий перед push

1. **Сделать правку** в коде
2. **Пройти полный аудит** (пункты 5.1–5.3)
3. **Только если ошибок = 0** → выполнить:
   ```bash
   git add -A
   git commit -m "..."
   git push origin main
   ```
4. **Сообщить** пользователю об отправке с указанием конкретных изменений

**ЕСЛИ НАЙДЕНЫ ОШИБКИ:**
- Исправить их ДО commit
- Не отправлять на GitHub с багами
- Доложить пользователю об найденных и исправленных ошибках
