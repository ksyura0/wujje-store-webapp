# Блок 5 — АУДИТ ПЛАТЕЖЕЙ: НАЙДЕННЫЕ БАГИ И РЕКОМЕНДАЦИИ

## 🔍 КРИТИЧЕСКИЕ НАХОДКИ

### 1. ⚠️ БАГ: Отсутствие проверки баланса перед покупкой

**Место**: Функция обработки платежей (строка ~2370+)  
**Проблема**: Код не проверяет, достаточно ли TON на балансе перед отправкой платежа  
**Риск**: Высокий - пользователь может потратить деньги впустую  

**Решение**:
```js
// ДОБАВИТЬ проверку:
if (order.ton && tonBalance < order.ton) {
  showError("Недостаточно TON. Требуется: " + order.ton + ", имеется: " + tonBalance);
  return;
}
```

---

### 2. ⚠️ БАГ: Нет защиты от дублей транзакций

**Место**: Система обработки платежей  
**Проблема**: Если пользователь дважды клинет кнопку оплаты, платёж может пройти дважды  
**Риск**: КРИТИЧЕСКИЙ - потеря денег пользователя  

**Решение**:
```js
// ДОБАВИТЬ на начало функции обработки:
const processedTxns = JSON.parse(localStorage.getItem("processed_txns") || "{}");
const txnKey = `${order.id}_${Date.now() / 60000 | 0}`; // уникальный ключ на минуту

if (processedTxns[txnKey]) {
  showError("Платёж уже обрабатывается, пожалуйста ждите...");
  return;
}

processedTxns[txnKey] = true;
localStorage.setItem("processed_txns", JSON.stringify(processedTxns));

// После успеха - очистить
delete processedTxns[txnKey];
```

---

### 3. ⚠️ БАГ: Молчаливые ошибки (нет логирования)

**Место**: Обработка платежей  
**Проблема**: Если платёж упадёт, нет записи об ошибке → невозможно отладить  
**Риск**: Высокий - невидимые проблемы  

**Решение**:
```js
// ОБЕРНУТЬ в try-catch с логированием:
try {
  // ... платёж ...
} catch (error) {
  console.error(`[Payment Error] Order: ${order.id}, Error: ${error.message}`, error);
  logPaymentError(order.id, error.message, tonBalance);
}
```

---

### 4. ⚠️ БАГ: Нет таймаута для Fragment запросов

**Место**: Обработка TON платежей  
**Проблема**: Если запрос "зависнет", UI блокируется навеки  
**Риск**: Высокий - UI freeze  

**Решение**:
```js
// ДОБАВИТЬ таймаут:
const paymentPromise = sendTonPayment(order);
const timeoutPromise = new Promise((_, reject) => 
  setTimeout(() => reject("Таймаут платежа (30сек)"), 30000)
);

try {
  await Promise.race([paymentPromise, timeoutPromise]);
} catch (error) {
  if (error.includes("Таймаут")) showError("Платёж слишком долго обрабатывается. Попробуйте ещё раз.");
}
```

---

### 5. ⚠️ БАГ: Нет валидации входных данных заказа

**Место**: Функция createOrder()  
**Проблема**: Если order.rub = -100, система может сломаться  
**Риск**: Средний - инъекция данных  

**Решение**:
```js
// ДОБАВИТЬ валидацию:
if (order.rub <= 0 || order.ton <= 0) {
  throw new Error("Invalid price");
}
if (!order.id || order.id.length === 0) {
  throw new Error("Invalid order ID");
}
```

## 📊 СИСТЕМА ПОПОЛНЕНИЯ БАЛАНСА

### ✅ Плюсы текущей реализации:
- Расчёты баланса выглядят правильными
- Есть базовая защита от повторных запросов
- История транзакций логируется

### ⚠️ Найденные проблемы:

#### 1. Возможные зависшие статусы
**Проблема**: Если платёж в состоянии "pending" > 5 минут, нет механизма отката  
**Решение**: Добавить expiration timestamp для pending платежей

#### 2. Нет retry-логики
**Проблема**: Если топ-ап не сработал с первого раза, нет автоматического повтора  
**Решение**: Добавить retry с exponential backoff (1s, 2s, 4s, 8s)

#### 3. Баланс может рассинхронизироваться
**Проблема**: Если вкладка закроется во время обновления, баланс может не синхронизироваться  
**Решение**: Проверять баланс при загрузке страницы через fetchTonBalance()
