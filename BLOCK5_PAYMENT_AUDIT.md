## 1️⃣ Аудит Telegram Stars автовыдачи через Fragment

### Критические области для проверки:

```
Нужно найти в index.html:
✓ Функции обработки платежей (processPayment, confirmOrder и т.д.)
✓ Проверка баланса TON перед покупкой
✓ Логирование транзакций (transaction ID, timestamp)
✓ Защита от дублей (duplicate transaction check)
✓ Обработка ошибок и retry-механизмы
```

### Вопросы для проверки:

1. **Есть ли проверка баланса TON перед покупкой?**
   - Нужна: `if (tonBalance < requiredAmount) { showError(...) }`
   - Опасно: Если пытаемся потратить больше, чем есть

2. **Как защита от дублей транзакций?**
   - Должна быть: таблица processed_txn_ids или localStorage ключ
   - Опасно: Если нету, юзер может повторить транзакцию дважды

3. **Логирование ошибок?**
   - Нужно: console.error, localStorage.logs или backend отправка
   - Опасно: Молчаливые ошибки без логов

4. **Таймауты для Fragment запросов?**
   - Нужны: setTimeout, Promise.race()
   - Опасно: Бесконечное ожидание = зависший UI

### Алгоритм поиска:

```bash
# Шаг 1: Найти главные функции
grep -n "processPayment\|confirmOrder\|buyWith\|purchase" index.html

# Шаг 2: Найти обращения к балансу
grep -n "tonBalance\|fetchTonBalance\|balance.*check" index.html

# Шаг 3: Найти логирование ошибок
grep -n "console.error\|try.*catch\|error.*handler" index.html

# Шаг 4: Найти защиту от дублей
grep -n "txn.*id\|transaction.*id\|duplicate\|already.*processed" index.html
```

## 2️⃣ Аудит системы пополнения баланса

### Проверяемые элементы:

1. **Корректность расчётов**
   - Формула: `newBalance = currentBalance + topupAmount`
   - Проверить: нет ли ошибок в арифметике

2. **Зависшие статусы**
   - Нужна логика: timeout → retry или cancel
   - Опасно: Если топ-ап застрял в состоянии "pending"

3. **Защита от отрицательного баланса**
   - Нужна: `if (newBalance < 0) reject()`
   - Опасно: Если баланс может стать отрицательным

4. **Лишний код**
   - Поискать: мёртвый код, старые функции, дебаг-переменные
   - Удалить: неиспользуемые variable/функции
